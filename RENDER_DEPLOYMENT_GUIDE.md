## Step-by-Step Deployment

### Step 1: Prepare Your Repository (5 minutes)

The `render.yaml` file has already been created in your repository root!

**Verify it exists:**
```bash
ls render.yaml
# Should show: render.yaml
```

**Commit and push:**
```bash
git add render.yaml
git commit -m "Add Render deployment configuration"
git push origin main
```

---

### Step 2: Create Render Account (2 minutes)

1. Go to https://render.com
2. Click "Get Started"
3. Sign up with GitHub
4. Authorize Render to access your repositories

---

### Step 3: Deploy from Dashboard (10 minutes)

#### Option A: Blueprint Deploy (Recommended - Easiest)

1. **Go to Render Dashboard**
   - https://dashboard.render.com

2. **Click "New +"** → **"Blueprint"**

3. **Connect Repository**
   - Select your `onbfinaldev_clean` repository
   - Render will detect `render.yaml` automatically

4. **Configure Blueprint**
   - Service Group Name: `hotel-onboarding`
   - Branch: `main`
   - Click "Apply"

5. **Render will automatically create:**
   - ✅ Backend web service
   - ✅ Frontend static site
   - ✅ PostgreSQL database
   - ✅ All connections between them

#### Option B: Manual Deploy (More Control)

If you prefer manual setup:

**3.1 Create Database First**
```
1. Click "New +" → "PostgreSQL"
2. Name: hotel-onboarding-db
3. Database: hotel_onboarding
4. User: admin
5. Region: Oregon (or closest to you)
6. Plan: Starter ($7/month)
7. Click "Create Database"
```

**3.2 Create Backend Service**
```
1. Click "New +" → "Web Service"
2. Connect your GitHub repository
3. Name: hotel-onboarding-backend
4. Region: Oregon
5. Branch: main
6. Root Directory: backend
7. Runtime: Python 3
8. Build Command: pip install -r requirements.txt
9. Start Command: gunicorn app.main_enhanced:app --workers 4 --worker-class uvicorn.workers.UvicornWorker --bind 0.0.0.0:$PORT
10. Plan: Starter ($25/month)
11. Click "Create Web Service"
```

**3.3 Create Frontend Service**
```
1. Click "New +" → "Static Site"
2. Connect your GitHub repository
3. Name: hotel-onboarding-frontend
4. Branch: main
5. Root Directory: frontend/hotel-onboarding-frontend
6. Build Command: npm install && npm run build
7. Publish Directory: dist
8. Click "Create Static Site" (FREE!)
```

---

### Step 4: Configure Environment Variables (8 minutes)

#### Backend Environment Variables

Go to your backend service → "Environment" tab:

**Required Variables:**
```bash
# Database (auto-populated if using Render PostgreSQL)
DATABASE_URL=postgresql://user:pass@host/db  # Auto-filled

# Supabase (if using)
SUPABASE_URL=https://your-project.supabase.co
SUPABASE_KEY=your-supabase-anon-key

# JWT Secret (auto-generated by Render)
JWT_SECRET=auto-generated-value

# Email Configuration
SMTP_HOST=smtp.gmail.com
SMTP_PORT=465
SMTP_USERNAME=your-email@gmail.com
SMTP_PASSWORD=your-gmail-app-password
SMTP_FROM_EMAIL=your-email@gmail.com
SMTP_FROM_NAME=Hotel Onboarding System

# Frontend URL (update after frontend deploys)
FRONTEND_URL=https://hotel-onboarding-frontend.onrender.com

# Environment
ENVIRONMENT=production
PYTHON_VERSION=3.12
```

**Optional Variables:**
```bash
# Groq API (for OCR)
GROQ_API_KEY=your-groq-api-key

# Google Cloud (for OCR)
GOOGLE_CREDENTIALS_BASE64=your-base64-credentials
GOOGLE_PROJECT_ID=your-project-id
```

#### Frontend Environment Variables

Go to your frontend service → "Environment" tab:

```bash
# Backend API URL (update after backend deploys)
VITE_API_URL=https://hotel-onboarding-backend.onrender.com/api

# Supabase (if using)
VITE_SUPABASE_URL=https://your-project.supabase.co
VITE_SUPABASE_ANON_KEY=your-supabase-anon-key
```

## Post-Deployment Configuration

### Custom Domain (Optional)

1. **Go to Frontend Service** → "Settings" → "Custom Domain"
2. **Add your domain**: `yourdomain.com`
3. **Add DNS records** (provided by Render):
   ```
   Type: CNAME
   Name: @
   Value: hotel-onboarding-frontend.onrender.com
   ```
4. **SSL Certificate**: Automatically provisioned by Render

### Database Backups

**Automatic Backups** (included):
- Daily backups on Starter plan
- 7-day retention
- Point-in-time recovery on Pro plan

**Manual Backup**:
1. Go to Database → "Backups"
2. Click "Create Backup"
3. Download or restore as needed

### Monitoring

**Built-in Metrics**:
- CPU usage
- Memory usage
- Request count
- Response time
- Error rate

**Access Logs**:
1. Go to Service → "Logs"
2. Real-time log streaming
3. Search and filter logs

## Troubleshooting

### Build Fails

**Backend build fails:**
```bash
# Check Python version
# In render.yaml, ensure: PYTHON_VERSION=3.12

# Check requirements.txt
# Make sure all dependencies are listed

# View build logs in Render dashboard
```

**Frontend build fails:**
```bash
# Check Node version
# Render uses Node 20 by default

# Check package.json
# Ensure all dependencies are listed

# Clear build cache
# Settings → "Clear Build Cache & Deploy"
```

### Service Won't Start

**Check logs:**
1. Go to Service → "Logs"
2. Look for error messages
3. Common issues:
   - Missing environment variables
   - Database connection failed
   - Port binding issues

**Database connection issues:**
```bash
# Verify DATABASE_URL is set
# Should be auto-populated by Render

# Check database is running
# Go to Database → ensure "Available" status
```

### Slow First Request

**Render free tier sleeps after 15 minutes of inactivity**

Solutions:
1. Upgrade to paid plan (no sleep)
2. Use a cron job to ping every 10 minutes
3. Accept 30-second cold start on first request
